# Спецификация REST API

**Версия:** 1.0  
**Статус:** проект контракта для целевого FastAPI backend. Эндпоинты ещё не считаются реализованными.

## 1. Общие правила

- Base path: `/api/v1`.
- Протокол: HTTPS в production.
- Формат: JSON UTF-8.
- Даты и время: ISO 8601, UTC.
- Идентификаторы запусков ETL: целые числа, если таковы идентификаторы в текущей БД.
- Пагинация: `page` начинается с 1; `page_size` по умолчанию 25, максимум 100.
- Все фильтры аналитики должны использовать одинаковую семантику.
- Значения фильтров передаются параметрами URL; секреты в URL запрещены.
- Для денежных величин всегда возвращать валюту и признак gross/net.
- Не возвращать description по умолчанию в списках вакансий.

## 2. Общие параметры фильтрации

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `date_from` | date | нет | Нижняя граница даты публикации |
| `date_to` | date | нет | Верхняя граница даты публикации |
| `region` | string | нет | Название региона из доступных значений |
| `role` | string | нет | Профессиональное направление |
| `origin` | string | нет | `api`, `import`, `synthetic` |
| `currency` | string | нет | Валюта сравнения зарплат |
| `gross` | boolean | нет | true — gross, false — net |
| `min_n` | integer | нет | Минимальный размер группы, диапазон 3–30 |

Если фильтр не передан, он не ограничивает выборку. Значение `origin=synthetic` позволяет явно отделить демо-данные от рыночных.

## 3. Формат ошибок

Все ошибки имеют общий формат:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Параметр page_size должен быть от 1 до 100",
    "request_id": "req_example"
  }
}
```

| HTTP | Код | Значение |
|---|---|---|
| 400 | `VALIDATION_ERROR` | Неверные параметры |
| 401 | `UNAUTHENTICATED` | Пользователь не аутентифицирован |
| 403 | `FORBIDDEN` | Нет права на операцию |
| 404 | `NOT_FOUND` | Объект не найден |
| 409 | `CONFLICT` | Конфликт состояния/запуска |
| 422 | `UNPROCESSABLE_ENTITY` | Формат корректен, но данные не проходят проверку |
| 429 | `RATE_LIMITED` | Превышен лимит запросов |
| 500 | `INTERNAL_ERROR` | Внутренняя ошибка без stack trace |
| 503 | `DEPENDENCY_UNAVAILABLE` | Недоступна БД или внешний источник |

## 4. Эндпоинты

### 4.1. Health check

`GET /api/v1/health`

Проверяет состояние backend. Внешние подробности инфраструктуры не раскрываются.

Ответ 200:
```json
{
  "status": "ok",
  "version": "1.0.0"
}
```

### 4.2. Сводка

`GET /api/v1/overview`

Параметры: общие фильтры.

Ответ:
```json
{
  "filters": {
    "date_from": "2026-01-01",
    "date_to": "2026-01-31",
    "region": null,
    "role": null,
    "origin": "api"
  },
  "sample": {
    "vacancies": 250,
    "employers": 183
  },
  "salary": {
    "currency": "RUB",
    "gross": false,
    "comparable_count": 23,
    "median": 220000.0,
    "mean": 225000.0
  },
  "salary_disclosure": {
    "count": 68,
    "share": 0.272
  },
  "top_skill": {
    "name": "Python",
    "vacancies": 248
  }
}
```
Числа приведены только как пример формы ответа, не как реальные показатели.

### 4.3. Справочники фильтров

`GET /api/v1/filters/options`

Ответ:
```json
{
  "regions": ["Москва", "Казань"],
  "roles": ["Программист, разработчик"],
  "origins": ["api", "import"],
  "date_min": "2026-01-01",
  "date_max": "2026-01-31",
  "total": 250
}
```

### 4.4. Каталог вакансий

`GET /api/v1/vacancies`

Параметры:
- общие фильтры;
- `q` — поиск по названию и описанию;
- `skills` — повторяемый параметр, вакансия должна содержать все указанные навыки;
- `experience`, `employment` — повторяемые параметры;
- `salary_min_rub` — минимальная известная граница зарплаты в RUB;
- `sort` — белый список: `published_desc`, `published_asc`, `salary_desc`, `salary_asc`, `title_asc`;
- `page`, `page_size`.

Ответ:
```json
{
  "items": [
    {
      "id": 123,
      "title": "Python-разработчик",
      "employer_name": "Пример",
      "region_name": "Казань",
      "experience": "От 1 года до 3 лет",
      "salary": {
        "from": 150000,
        "to": 220000,
        "currency": "RUB",
        "gross": false,
        "kind": "range"
      },
      "published_at": "2026-01-15T10:30:00Z",
      "url": "https://hh.ru/vacancy/123",
      "data_origin": "api"
    }
  ],
  "total": 1,
  "page": 1,
  "page_size": 25
}
```

### 4.5. Одна вакансия

`GET /api/v1/vacancies/{vacancy_id}`

Возвращает расширенную карточку, включая описание только для выбранной вакансии, если оно сохранено. Не возвращать внутренние технические поля БД.

### 4.6. Зарплатная аналитика

`GET /api/v1/analytics/salaries`

Параметры: общие фильтры, `currency`, `gross`, `min_n`.

Ответ:
```json
{
  "basis": {"currency": "RUB", "gross": false},
  "overall": {"n": 23, "median": 220000, "mean": 225000, "p25": 180000, "p75": 270000},
  "by_region": [
    {"name": "Казань", "n": 8, "median": 210000, "sufficient": true}
  ],
  "method": "Только корректные вилки от–до; валюты и gross/net не смешиваются"
}
```

### 4.7. Навыки

`GET /api/v1/analytics/skills`

Параметры: общие фильтры, `limit` (1–100), `source` (если доступен выбор источника навыков).

Ответ содержит список навыков, число вакансий, долю от выборки и метаданные окна сравнения, если запрошен тренд.

### 4.8. География

`GET /api/v1/analytics/regions`

Параметры: общие фильтры, `limit`.

Ответ содержит регион, количество вакансий, долю выборки, количество сопоставимых зарплат и медиану при достаточном n.

### 4.9. Прогноз

`GET /api/v1/analytics/forecast`

Ответ:
```json
{
  "available": false,
  "reason": "Недостаточно исторических точек для надёжной проверки",
  "horizon_days": null,
  "mae": null,
  "baseline_mae": null,
  "points": []
}
```
Если прогноз доступен, ответ обязан содержать горизонт, историю, прогнозные точки, MAE и baseline MAE. Нельзя скрывать недостаток истории.

### 4.10. История ETL

`GET /api/v1/etl/runs`

Параметры: `page`, `page_size`, `status`, `origin`.

Ответ содержит ID, источник, описание, время начала/окончания, статус, получено, валидно, отклонено, дублей, вставлено, обновлено, без изменений, безопасное сообщение об ошибке.

### 4.11. Запуск сбора

`POST /api/v1/etl/collect`

Только для оператора. Токен hh.ru не передаётся в теле запроса — он берётся из серверных секретов.

Запрос:
```json
{
  "queries": ["Python разработчик"],
  "areas": ["1"],
  "max_vacancies": 100,
  "fetch_details": false
}
```

Ответ 202:
```json
{
  "run_id": 42,
  "status": "queued",
  "status_url": "/api/v1/etl/runs/42"
}
```

На первом этапе это контракт для фонового выполнения. Реализация должна использовать очередь/worker либо ограниченный механизм фоновых задач; не выполнять большой сбор в долгом HTTP-запросе.

### 4.12. Статус ETL-запуска

`GET /api/v1/etl/runs/{run_id}`

Возвращает состояние `queued`, `running`, `success`, `partial`, `failed`, счётчики и безопасное описание результата.

## 5. Контракт зарплаты

Объект зарплаты:
```json
{
  "from": 100000,
  "to": 150000,
  "currency": "RUB",
  "gross": false,
  "kind": "range"
}
```

`kind` принимает значения `range`, `from`, `to`, `none`, `invalid`. Нельзя вычислять медиану на основании односторонних значений или объединять разные валюты/признаки gross-net.

## 6. Кэширование

- Справочники фильтров могут иметь короткий TTL.
- Аналитические ответы кэшируются только с учётом всех фильтров в ключе.
- После успешной ETL-загрузки кэш должен инвалидироваться.
- Статус ETL и health не кэшируются длительно.

## 7. Безопасность и ограничения

- CORS — только разрешённые frontend origins.
- Операции ETL защищены правом оператора.
- Максимальные page_size, limit и max_vacancies ограничены сервером.
- Все SQL-параметры передаются безопасно.
- Не раскрывать токены, пароли, SQL и stack trace.
- Не выполнять запросы к hh.ru из браузера.
- Не обходить CAPTCHA, 401/403 и правила API.

## 8. Версионирование и совместимость

Изменения, несовместимые с текущими клиентами, должны выходить в новой версии пути API. OpenAPI-документация FastAPI должна соответствовать этому документу. Примеры JSON являются схемами формы, а не гарантированными реальными данными.
